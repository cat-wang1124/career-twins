    Notes from the build

    • 01 Uses Exa's findSimilar for URLs and semantic search for résumé text. Both route to category="people".
    • 02 "Why this match" comes from Exa's summary parameter on /contents — cheaper than a second LLM hop, and grounded in the candidate's own page.
    • 03 Enrichment fans out across a thread pool of ten — one /contents call per twin, all running in parallel.
    • 04 Results cache for seven days in a local JSON file so repeated demos don't burn API credits.
